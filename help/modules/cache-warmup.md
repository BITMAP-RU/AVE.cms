# Автоматический прогрев кеша

Модуль `cache_warmup` заранее открывает публичные страницы, чтобы первый
посетитель не ждал построения тяжёлых кешей.

Очередь обновляется после полного сброса кеша, сохранения опубликованного
документа, ежедневного задания и ручного запуска. Полный план включает главную
страницу, опубликованные документы и все активные товарные фиды. Примерно на
80% собственного TTL модуль напрямую и принудительно обновляет внутренний кеш
фида, поэтому робот площадки не оплачивает холодную генерацию. Это работает и
для закрытых фидов, но их токены не сохраняются и не показываются в очереди.
Фид с TTL `0` повторно прогревается только полным планом.

Настройка **URL за один запуск** ограничивает нагрузку. Значение `10–15`
подходит обычному сайту: планировщик обрабатывает следующую пачку раз в минуту,
а не открывает весь сайт сразу.

После трёх ошибок URL ждёт нового полного плана. В журнале остаются HTTP-статус,
время ответа и текст ошибки. Окончательная ошибка после третьей попытки
появляется в колокольчике панели.

Базовый URL можно оставить пустым, тогда используется домен запроса
планировщика. На production рекомендуется задать канонический HTTPS URL.
Исходящий клиент проверяет DNS и запрещает private/reserved адреса.

Для автоматической обработки нужен [Планировщик](scheduler.md). Публичный CLI
не требуется.
